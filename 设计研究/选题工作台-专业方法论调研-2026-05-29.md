# 选题工作台专业方法论调研

## TL;DR

1. **判断"两个词该不该放同一页"的黄金信号是 SERP 重合度**——不是语义相似、不是关键词字面，而是两个词的 Google top10 里共享多少个相同 URL。这是整个建图体系的物理地基，原因是它直接复刻了"Google 自己怎么看这两个词"。行业共识阈值：top10 共享 **3 个 URL（30%）是宽松基线，4 个（40%）是大多数场景的标准，5-6 个用于头部品牌高度同质的红海**。0-1 个 = 必须拆成两页。
2. **专业建图不是单层"聚类"，而是两层结构**：先按 SERP 重合把关键词聚成"页级 cluster（一个 cluster = 一个页）"，再用语义/NLP 把这些 cluster "聚成 cluster"（topical cluster / silo），后者才对应你的"支柱页 hub"。Keyword Insights 和 Keyword Cupid 都是这个双层逻辑。
3. **意图分组与 SERP 聚类是互补两条线，不是二选一**：意图分组（informational/commercial/transactional/navigational）决定"这一页该是什么形态（指南/对比/产品/工具）"，SERP 聚类决定"哪些词进同一页"。专业流程是先粗筛意图、再在意图组内跑 SERP 聚类。一页里绝不混合冲突意图（教育型 + 交易型不可同页，否则 CTA 自相矛盾）。
4. **蚕食（cannibalization）= 同关键词 + 同意图的两个自有页互相竞争**。检测靠 GSC（同一 query 下出现 ≥2 个自有 URL 且各占可观曝光份额）或 `&filter=0` 看真实多 URL 排名；预防靠"一个 URL = 一个主关键词 + 一个意图"的关键词地图（keyword map）这张表本身。这正是你这个工作台的核心产物。
5. **工具界面高度趋同于三件事**：源池（表格/列表）→ 分组（pillar-subpage 层级表 + 可视化）→ 详情面板（点开一个页看它绑了哪些词 + 信号）。**可视化普遍用气泡图/六边形蜂巢图/树状 dendrogram/网络图来呈现 cluster 关系，但真正的"绑定操作"几乎都还停在表格层**——这恰恰是你做"手动拖拽绑定工作台"的差异化空位。

## A. 方法论：从关键词到 pillar-cluster 主题地图

### 发现 1 — Pillar / Cluster 的标准定义与关系

- **Topic cluster（主题集群）= 三个部件**：一个 pillar page（支柱页/hub，广而全地覆盖大主题）+ 多个 cluster page（集群页/spoke，每个深挖一个子主题）+ 把它们双向连起来的内链。HubSpot 在 2017 年提出并普及，已成行业标准架构。
- **pillar 与 cluster 的分工**：pillar 不追求把每个问题答到底，而是"定义整个生态/地图"，每个子主题点到为止后立刻给出通往深度资源的链接（spoke）；cluster page 才是深挖、证明 E-E-A-T 深度的地方。
- **数量级共识**：成熟 cluster 通常 **8-20 个 spoke**（最低 8-12 才不被视为"薄覆盖"），pillar 字数 3,000-5,000，spoke 1,500-2,500。单个页级 cluster 内通常绑 **5-20 个关键词**。
- **一个重要澄清（设计时别踩）**：pillar-cluster 是**链接架构**（用双向内链建话题权威）；Hub-Spoke / 3H（Hero-Hub-Hygiene）是**内容生产/预算分层**，两者常被混用但不是一回事。你的工作台做的是前者（链接架构 + 选题地图）。
- **来源**：[Search Engine Land: Topic clusters & pillar pages](https://searchengineland.com/guide/topic-clusters)｜[HubSpot Topic Clusters 原始报告 PDF](https://cdn2.hubspot.net/hubfs/53/assets/hubspot.com/research/reports/Topic%20Clusters%20SEO%20Report.pdf)｜[GEO Glossary: Topic clusters](https://aisearchglossary.com/terms/topic-clusters)｜[IndexableAI: Pillar-Cluster vs Hub-Spoke](https://indexableai.com/blog/pillar-cluster-hub-spoke/)
- **置信度**：多源验证

### 发现 2 — Pillar 如何选定（判据）

综合多源，一个候选词/主题值得被定为 pillar，看四条：

1. **主题广度（hub 价值）**：能不能当 20-30 篇文章的"伞"？HubSpot 的 Leslie Ye 给的判定句很实用——"这一页能不能回答搜 X 的人的每一个问题，**并且**广到足以作为 20-30 篇帖子的伞？"。"Marketing"太宽，"E-commerce email marketing automation"才是合适粒度。
2. **能在写 pillar 前先列出 15-30 个子主题**：写不出子主题集的 pillar，最后会变成一个"什么都排不上"的散页。
3. **头部词 / 高搜索量 / 宽意图**：pillar 通常对应一个高量、宽意图的 head term（如 "Technical SEO" "CRM software"），spoke 对应 long-tail。
4. **商业中心性 / 与业务对齐**：pillar 要直接映射"你的业务做什么 + 受众搜什么"的交集，不是单纯量大。
- **来源**：[ContentGrip: Internal linking & topic clusters](https://www.contentgrip.com/internal-linking-topic-clusters-guide/)｜[GEO Glossary](https://aisearchglossary.com/terms/topic-clusters)｜[SearchEngineZine: Topic Cluster Model](https://searchenginezine.com/on-page/links/topic-cluster-model/)
- **置信度**：多源验证

### 发现 3 — 关键词聚类的三种主流方法

#### 3a. SERP 重合度聚类（SERP overlap clustering）——黄金信号

- **原理**：两个词各自抓 Google top10 的 URL 列表，算交集。如果重合多，说明 Google 自己已经判定"一页能同时满足这两个 query"，应该放一页；几乎不重合说明 Google 看作不同意图，必须拆页。它是唯一直接复刻"Google 怎么想"的信号，所以是判断同页/拆页的黄金标准。
- **阈值（行业共识区间）**：
  - **3 个共享 URL（30%）= 宽松基线**，autorank/HubSpot/多家 MCP 工具默认。
  - **4 个共享 URL（40%）= 大多数场景的标准**（B2B SaaS operator framework 的默认值）。
  - **5-6 个**用于"top10 被同 5-7 个品牌霸占"的高同质红海（CRM/项目管理/会计软件），防止过度合并。
  - **3 个**用于"SERP 尚未固化"的新兴垂类。
  - **0-1 个 = 独立页（standalone）**，自成一个单词 cluster。
  - 合并经验：**60-70%+ top10 重合且页面类型相同 → 合并**；**重合 <40% 或意图从 informational 漂到 commercial → 拆页**。
- **手动 vs 自动的边界**：手动逐对比 SERP 只适合 <200 词的小表；超过就必须自动化（2000 词 = 200 万对组合，人做不了也做不准）。
- **关键工程细节**：实务做法是先抓每个词 top10 URL → 算两两交集 → **贪心建簇（先合并重合最高的对）** → 达到阈值的进同簇 → 没匹配上的成单词簇。簇内取最高搜索量的词作 primary keyword（决定 title/H1）。
- **来源**：[HubSpot: Keyword clustering 2026](https://blog.hubspot.com/marketing/keyword-clustering)｜[Technotize: B2B SaaS operator framework](https://technotize.io/insights/keyword-clustering-b2b-saas)｜[SERPs.io](https://serps.io/blog/keyword-clustering-seo-strategy)｜[Keywordly](https://keywordly.ai/blog/serp-keyword-clustering-tool)｜[Autorank free tool](https://autorank.so/free-tools/keyword-clustering-tool)｜[mcp-serp-clustering (GitHub, 算法实现)](https://github.com/dredozubov/mcp-serp-clustering)
- **置信度**：多源验证（阈值区间有差异已如实标出）

#### 3b. 语义 / embedding 聚类

- **原理**：把关键词（或页面内容）向量化（如 sentence-transformers / all-MiniLM-L6-v2），按向量距离聚类。优点：快、不用抓 SERP、能发现 SERP 还没固化时的"语义近邻"；缺点：会把字面/语义像但意图不同的词错并（如 informational 和 commercial 撞一起），精度不如 SERP。
- **何时用**：① 大列表的预聚类/粗分；② "cluster 的 cluster"——把页级簇再聚成 topical silo（NLP 找簇间语义关系，对应 pillar 划分）；③ SERP 数据贵或拿不到时的廉价替代。
- **2026 共识：混合（SERP + 语义）精度最高**——SERP 定页级边界，语义补 SERP 抓不到的关系。
- **来源**：[DesignCopy: AI Keyword Clustering 2026](https://designcopy.net/en/ai-keyword-clustering-guide/)｜[Keyword Insights: Topical Clusters 文档](https://docs.keywordinsights.ai/learning-center/the-features/topical-clusters)
- **置信度**：多源验证

#### 3c. 意图（intent）分组

- **原理**：按四类意图（informational / commercial / transactional / navigational）先分组，再在组内做 SERP/语义聚类。意图分组的产物不是"哪些词同页"，而是"这一页该长成什么形态 + 该放在 buyer journey 哪一段"。
- **何时用**：永远作为**前置粗筛**——它和 SERP 聚类是互补两条线（意图组管 portfolio 平衡，SERP 簇管内容生产单元）。
- **来源**：[Technotize](https://technotize.io/insights/keyword-clustering-b2b-saas)（明确把 semantic clustering 和 intent clustering 作为互补两套）
- **置信度**：多源验证

### 发现 4 — "一页还是拆两页"的决策规则

把上面的阈值收成一个可落地的判定：

| 条件 | 决策 |
|---|---|
| top10 重合 ≥ 4 个 URL（≥40%）**且**页面类型/意图相同 | 合并为一页，最高量词作 primary |
| top10 重合 60-70%+ **且**同意图 | 强合并 |
| top10 重合 < 40% **或**意图从 informational 漂到 commercial/transactional | 拆成两页（互相内链） |
| top10 重合 0-1 个 | 独立页 |
| 同一关键词同时跑出 informational + commercial 两类 SERP（fragmented intent） | **可故意做两页**（一篇内容页 + 一个产品页），在 SERP 里占两个位，互不蚕食——前提是两页意图清晰区隔 |

**反向规则（避免错误合并）**：①under-clustering（把本该一页的拆成 3 个薄页，如 "best CRM for small business" / "small business CRM software" / "CRM tools for small businesses" 明明 top10 共享 8-9 个 URL）；②over-clustering（阈值太松，一个簇 50+ 词，宽到一页排不上）。
- **来源**：[Keywordly](https://keywordly.ai/blog/serp-keyword-clustering-tool)｜[Keyword Insights 上下文/意图文档](https://docs.keywordinsights.ai/understanding-the-output/how-to-interpret-context-intent)（"fragmented intent 做两页"出处）
- **置信度**：多源验证

### 发现 5 — 搜索意图 → 页面类型匹配

| 意图 | 用户目标 | 查询信号词 | 该建的页面类型 | CTA |
|---|---|---|---|---|
| Informational | 学习/理解 | how, what, why, guide, tutorial, definition, tips | 博客/指南/教程/FAQ/词条 | 软 CTA、下一篇 |
| Commercial（investigation） | 比较/筛选选项 | best, top, vs, alternative, review, compare | 对比页/榜单（listicle）/评测 | demo/case study/多个 CTA |
| Transactional | 立即行动（买/注册/下载/约 demo） | buy, pricing, trial, demo, download, quote | 产品页/定价页/落地页/注册页 | 单一强 CTA |
| Navigational | 直达某品牌/页面 | [brand] login, support, [brand] vs | 首页/登录页/品牌落地页 | 直达、零摩擦 |

**核心原则（设计时做成硬告警）**：
- **一页只服务一个主导意图**。判定主导意图最快的办法是看那个词的 top10 SERP 现在被什么形态霸占（全是 listicle = commercial；全是长文指南 = informational；是品牌首页 = navigational）。
- **不要在一页混冲突意图**：如果一页需要两个互相矛盾的 CTA（"了解一下" vs "立即购买"），就必须拆页。意图相近、受众重叠度高（如 informational + 轻 commercial）可以一页 + 模块化分区；意图服务不同 buyer stage 的受众 → 拆两页互链。
- "best CRM" 是 commercial（要对比页），"Salesforce pricing" 是 transactional（要定价页）——这个灰区是最常被搞错的。
- **来源**：[SEOWebster: Navigational vs Transactional + intent-to-page 映射](https://seowebster.com/blog/navigational-vs-transactional-keywords)｜[Search Engine Land: Search Intent 指南](https://searchengineland.com/guide/search-intent-seo)｜[Incremys: Search Intent Types 2026](https://www.incremys.com/en/resources/blog/search-intent-types)｜[DeepSmith: 一页/拆页/hub+spoke 三选一规则](https://deepsmith.ai/blog/seo-content-search-intent)｜[HaydenSchuster: 4 types 决策树](https://haydenschuster.com/seo-blog/content-strategy/4-types-of-search-intent/)
- **置信度**：多源验证

### 发现 6 — 关键词蚕食（cannibalization）检测与避免

- **定义（两条同时成立才算）**：两个自有页 ① 锁同一/近似关键词 ② 满足同一/近似意图 → 互相竞争、分散信号。注意：博客页 + 产品页共享一个 query 但意图不同 ≠ 蚕食（那是合法兄弟页）。
- **检测**：
  - **GSC Performance**：选一个 query → Pages 标签 → 是否 ≥2 个自有 URL 各占可观曝光份额（如 30%/70% 而非 95%/5%）。
  - **`&filter=0`**：在 Google 搜索 URL 末尾加，关闭 host clustering，看自己域名真实的多 URL 排名。
  - **严重度评分（可借鉴做你的告警分级）**：High = 两页位次差 <3 且曝光比 >0.5；Medium = 位次差 <5 且曝光比 >0.3；位次差很大（如 4 vs 22）或量很低 = 可能不用管。
- **修复（四选一）**：① 合并 + 301（内容大量重复、有一个明显更强）；② 各自重定向到不同意图/long-tail（两页都有合法用途）；③ canonical（功能性近重复必须共存，如产品页 + 筛选品类页）；④ 内链 + 改 title/H1 让两页差异显性化。
- **预防（= 你的工作台核心价值）**：维护一张 **keyword map / keyword-to-URL 表，每个 URL 绑一个 primary keyword + 一个意图**。发新内容前先 `site:` 查是否已有页。这张表本身就是防蚕食的物理屏障。
- **来源**：[Search Engine Land: Keyword cannibalization](https://searchengineland.com/guide/keyword-cannibalization)｜[Backlinko](https://backlinko.com/keyword-cannibalization)｜[Neil Patel](https://neilpatel.com/blog/keyword-cannibalization/)｜[Advanced GSC: 严重度评分公式](https://www.advancedgsc.com/blog/keyword-cannibalization-google-search-console)｜[GSC Wizard playbook](https://www.gscwizard.com/learn/playbooks/fix-cannibalization.html)
- **置信度**：多源验证

### 发现 7 — 主题覆盖 / 话题权威 / 覆盖缺口（coverage gap）

判断一个 pillar 的 cluster 是否覆盖全、缺哪些子主题，专业做法有四条信号源：

1. **People Also Ask（PAA）/ AlsoAsked.com**：把 PAA 当免费关键词工具，AlsoAsked 直接拉出 Google 的 PAA 问题树。每个 PAA 问题 = 一个该覆盖的子主题。竞品答了 5 个你只答 2 个 → 你输。
2. **Related searches + AI Overview / 精选摘要里出现的实体**：SERP 底部的相关搜索是"语义近邻"，没覆盖就是话题深度漏。
3. **竞品 cluster 逆向**：找真正的 SERP 竞争者 → 抽他们 pillar 页的子主题/实体/内链结构（哪些 awareness 指南连到哪些 decision 对比页）→ 找他们覆盖你没覆盖的（white space），以及他们的逻辑遗漏（如讲云合规却漏了 SOC 2）。
4. **子主题清单 + 覆盖打分**：LLM 把 pillar 拆成预期子主题树（可逐级下钻到 heading 层），对每个子主题标 Covered / Weak / Gap，给一个 0-100 覆盖分。一个常见加权：高重要度子主题占 50%、中 30%、整体覆盖 20%；>70 强，<40 大缺口。
- **现代缺口 ≠ 缺一个 exact-match 词**，而是缺一段语义关系 / 缺一类意图 / 缺原创数据（Information Gain）。
- **来源**：[Search Engine Land: SEO gap analysis](https://searchengineland.com/guide/gap-analysis)｜[TruSEO: Content gap via PAA/related](https://truseosolutions.com/blogs/content-gap-analysis-guide/)｜[Marketing Agent: PAA 建权威教程](https://marketingagent.blog/2026/04/14/tutorial-build-topical-authority-with-people-also-ask/)｜[QueryBurst: 覆盖打分/topic ring](https://queryburst.com/docs/site-intelligence/topics/)｜[Sunil Pratap: Topic Cluster Gap Analyzer 打分公式](https://sunilpratapsingh.com/tools/topic-cluster-gap-analyzer)｜[RankDots: 竞品实体覆盖 5 步](https://rankdots.com/blog/competitive-analysis)
- **置信度**：多源验证

### 发现 8 — 内链结构：pillar↔cluster 的 hub-and-spoke 最佳实践

- **三类链接，每一类都不能漏**：
  1. **pillar → 每个 spoke**：用描述性锚文本（反映 spoke 目标词，如 "complete guide to email segmentation"），放在上下文相关的段落里，**不要只堆在页尾一个链接列表**。
  2. **每个 spoke → pillar**：用 "back to our email marketing guide" 类锚文本，**理想位置在 spoke 正文前 200-300 字内**。这是整个架构里最重要的一条链接，作用是把 link equity 汇聚到 pillar 的 head term。
  3. **相关 spoke ↔ spoke 互链**：2-3 条上下文链接，形成"三角连接"（implementation↔migration↔data hygiene），增加簇内密度、提升 crawl 效率。
- **常见漏洞**：只记得 spoke→pillar，忘了 pillar→spoke，更很少做 spoke↔spoke——这种残缺结构会削弱整簇的权威流动。
- **锚文本纪律**：描述性、不重复。同一锚文本指向多个页 = 给 Google 发混乱信号（也是蚕食诱因）。
- **URL/IA 配套**：干净子目录（/crm/、/crm/migration/）、一致面包屑、pillar 能从导航发现（不只靠内链）。
- **来源**：[Search Engine Land: Topic clusters（互链最佳实践）](https://searchengineland.com/guide/topic-clusters)｜[Clarigital Digital Codex（三类链接表）](https://www.clarigital.com/codex/content-marketing/topic-clusters-pillar-pages/)｜[ContentGrip](https://www.contentgrip.com/internal-linking-topic-clusters-guide/)｜[Korvex Hub-and-Spoke 文档（链接覆盖率指标）](https://korvex.app/docs/methodology/methodology-hub-and-spoke)
- **置信度**：多源验证

### 发现 9 — 优先级打分（先做哪个页）

没有唯一公式，但有清晰的演化谱系，从简到全：

1. **最简（不推荐单用）**：`机会分 = 搜索量 / 关键词难度`。问题：KD 跨工具不可比，且忽略商业价值、当前排名、CTR。
2. **象限法（最实用的可视化）**：把 keyword 按 难度×价值 画四象限——
   - **Quick Wins（高价值低难度）**：最高优先，先做，造现金流。
   - **Strategic Bets（高价值高难度）**："money terms"，建长期 cluster + 外链地基，别指望速成。
   - **Authority Builders（低价值低难度）**：拉权威/邮件名单/自然外链的 informational 长尾。
   - **Resource Sinks（低价值高难度）**：直接避开。
3. **加权多因子（适合做成你工具里的 score 列）**：
   `Opportunity = 量×0.20 + 商业相关性×0.30 + 排名差距(距前三)×0.20 + CTR潜力×0.15 + (反向)难度×0.15`
   注意：**商业相关性权重最高（30%）**，因为不转化的流量没价值。
4. **简洁可手算版**：`Priority = (商业相关性 × 可赢度) / (KD + 1)`。例："seo" 量大相关性满分但可赢度=3、KD=95 → 分仅 0.31；"seo checklist for news sites" 相关 8、可赢 7、KD 22 → 2.43，后者才是好的下一步。
5. **收入导向版**：`潜在收入 = (月量 × 前三 CTR 20-30%) × 转化率 × AOV`。
- **两条专业心法**：① **难度评分要在优先级评分之后才进决策**，别让量和 KD 先污染商业判断；② **簇内词（in-cluster）的难度要打折**——你已有 cluster 权威时，一个显示 KD32 的词实际难度更低（一种做法：簇内词 KD-15）。
- **新站纪律**：DR 0-20 头半年只做 KD<30 的 Quick Wins。
- **来源**：[HMDigital: Keyword Opportunity Score（加权公式）](https://hmdigitalsolution.com/keyword-opportunity-score-calculation/)｜[TLSubmit: 四象限 + 收入公式](https://tlsubmit.com/how-to-prioritize-keywords-by-traffic-difficulty-and-revenue-potential/)｜[CurratedBrief: (相关×可赢)/(KD+1)](https://curratedbrief.com/keyword-prioritization-guide)｜[AISEOJournal: 4 维盈利打分 + 簇内 KD 折扣](https://aiseojournal.net/how-to-score-keywords-for-profitability-using-a-4-dimension-framework/)｜[Audit-content: 加权多准则矩阵](https://audit-content.com/calculators/priority-scoring/)
- **置信度**：多源验证

### 发现 10 — 通用工作流骨架（7 款高度趋同）

几乎所有工具都是这条线：**① 进料（输 seed / 上传自有 CSV / 连 GSC）→ ② 自动聚类（SERP 重合为主，部分加语义二次聚类）→ ③ 双层结构产出（Topics/Pillar 在上、Subpages/keywords 在下）→ ④ 详情面板（点开一个"页"看它绑了哪些词 + 该页的量/KD/意图/SERP）→ ⑤ 导出/转 brief/转写作**。

- **进料的人机分工**：所有工具都支持"自带数据(BYOD)"——上传从 Ahrefs/Semrush 导出的词 + 量 + KD，工具只负责聚类。这对你重要：**你的工作台可以只做"聚类信号 + 绑定工作台"，不必自建关键词数据库**。
- **来源**：[Keyword Insights 工作流文档](https://docs.keywordinsights.ai/learning-center/keyword-insights-tool-workflow)｜[Keyword Insights 聚类 3 步](https://docs.keywordinsights.ai/learning-center/the-features/keyword-clustering/README)｜[Surfer Topical Map 文档](https://docs.surferseo.com/en/articles/9383782-topical-map)｜[Semrush Keyword Strategy Builder KB](https://www.semrush.com/kb/1058-keyword-strategy-builder)｜[Ahrefs 即时聚类](https://ahrefs.com/blog/keyword-clustering-tools/)
- **置信度**：多源验证

### 发现 11 — 自动化 vs 人工决策的真实分界

- **几乎全自动的部分**：抓 SERP、算重合、建初始簇、分意图、取排名、选 primary、推荐 pillar——这些没人手动做（量太大）。
- **几乎都留给人工的部分**：① 调聚类阈值/算法强度(松紧)；② **看可视化后判断簇该不该合/拆**；③ 选哪些簇真正进 content plan/优先级排序；④ 把簇转成 brief 的取舍。
- **真正做"拖拽手动绑定"的只有 Frase**（drag-and-drop organization + connection strength indicators + 自然语言 Agent 分配）。Semrush/Ahrefs/Keyword Insights 的"绑定"基本停在表格层级（展开/折叠簇、Page Details 面板），**没有自由拖一个词到另一个页的交互**。
- **这是你的差异化空位**：市面工具是"自动聚类 → 你接受结果"，你要做的是"自动给信号 → 人手动建图/绑定 → 工具实时校验"。Frase 最接近你的设想，可作头号借鉴对象。
- **来源**：[Frase Clusters 功能页(拖拽/连接强度)](https://www.frase.io/features/clusters)｜[Frase Agent 功能页](https://www.frase.io/features/agent)｜[Keyword Cupid review(拖拽 mindmap)](https://marketingtoolpro.com/keyword-cupid-review/)
- **置信度**：多源验证

### 发现 12 — "一条词从未分配→绑进某页"的交互路径（各家做法）

- **Semrush**：Keyword Magic Tool 勾词 → "Send keywords" 送进 Keyword Strategy Builder → "Cluster this list" 自动归簇 → Topics & Pages 层级表里展开簇 → 点某页开 **Page Details 面板**看该页绑了哪些词 → 满意后"Write content"送写作。（绑定=自动归簇，人工只在簇间挑，**不能手动改某词归属**）
- **Keyword Insights**：上传/选词 → 设置阈值/意图 → 跑完看气泡图或表 → 点某簇的绿色高亮 primary 图标 → "add to brief / writer"。（绑定也是自动归簇）
- **Ahrefs**：粘词 → 点 "Clusters by Parent Topic" 标签 → 侧边栏出现分组 → 点一个 parent 钻进它的子主题 → 加入 list。（绑定=按 Parent Topic 归，人工只在 list 层组织）
- **Frase**（最接近你要的）：导内容→Agent 自动建议簇→**人工在可视图上拖拽把内容/词分配到某 pillar**→Agent 标缺口→一键建缺失文章。自然语言也能"把这些文章分到这个簇"。
- **设计启示**：现有工具的"未分配→已分配"几乎都是**算法先归位、人工只做组间搬运/接受**；真正的"一个未分配词 → 人手拖进某 pillar/cluster → 实时弹出 SERP 重合/意图/蚕食校验"这条交互链，市面上基本是空白。这正是"人机协作工作台"该独占的体验。
- **来源**：[Semrush blog: Send keywords→cluster→Page Details](https://www.semrush.com/blog/keyword-manager-clustering-tool/)｜[Ahrefs keyword grouping](https://ahrefs.com/blog/ke-keyword-grouping/)｜[Frase 4 步建簇](https://www.frase.io/features/clusters)
- **置信度**：多源验证

### 发现 13 — 可视化形态对照（选型参考）

- **气泡图 / 圈套圈（Keyword Insights）**：直观表达"簇的簇"，可按意图上色。适合"看整体话题地图 + 意图分布"。
- **六边形蜂巢图（Surfer）**：大六边形=主题、小六边形=文章，颜色双编码(覆盖度/难度)。适合"一眼看 white space 缺口 + easy win"。
- **Treemap 矩形树图（Ahrefs）**：矩形面积=搜索量。适合"按量快速排优先"。
- **Dendrogram 树状思维导图（Keyword Cupid）**：顶=大主题/中=silo/叶=页级，天然映射 silo 互链结构，节点颜色=cluster confidence。适合"层级建站 + 互链规划"。
- **交互式网络图 + 拖拽 + 连接强度线（Frase）**：最适合"人机协作建图/绑定"的形态——节点可拖、连线粗细表示关系强度。
- **层级表（Semrush/全员都有）**：pillar 行折叠展开 subpage 行 + 右侧详情面板。**这是真正"干活"的视图**，可视化图多用于"对客户/老板讲故事"。
- **设计启示**：可视化图(蜂巢/网络)负责"宏观叙事 + 找缺口"，**层级表 + 详情面板负责"逐词绑定 + 看信号"**——两者要并存，别只做炫的图。
- **来源**：[Keyword Insights 可视化文档](https://docs.keywordinsights.ai/understanding-the-output/how-to-interpret-clusters-with-in-app-visualizations)｜[Surfer Map Tab 文档](https://docs.surferseo.com/en/articles/9383782-topical-map)｜[Ahrefs Treemap](https://ahrefs.com/academy/how-to-use-ahrefs/keywords-explorer/related-terms)｜[Keyword Cupid dendrogram(AI Journal)](https://aijourn.com/keyword-cupid-upgrades-semantic-keyword-clustering-tool-with-retrained-machine-learning-models/)｜[Frase 可视 cluster map](https://www.frase.io/features/clusters)
- **置信度**：多源验证

## 来源冲突 / 待澄清

- **SERP 重合阈值无统一标准**：30%(3 URL) / 40%(4 URL) / 50%+ 各有出处，且取值依垂类同质度而变（红海调高、新兴垂类调低）。**结论：阈值应做成工具里用户可调的滑块，默认 4 个(40%)，并给出"红海调高/新兴调低"的提示**——不要硬编死一个数。
- **pillar/spoke 字数与 spoke 数量是启发式经验**，无官方数字。8-20 spoke、pillar 3000-5000 字是行业惯例区间，不是 Google 公开标准。

## 未解 / 待补

- 没有深挖 ClusterAI 的具体界面（仅从对比中得知其"基础表格、CSV 导出、学习曲线低、静态数据源"，可视化弱于 Keyword Cupid）。若需要可单独补。
- 各工具的"实时蚕食告警"做得都不深——市面上蚕食检测多是独立功能(GSC 类工具)，没和建图工作台缝在一起。这块缺乏可直接 benchmark 的成熟交互，是你要原创设计的部分。
