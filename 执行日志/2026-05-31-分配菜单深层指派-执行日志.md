# 执行日志 · 分配菜单深层指派（画出孙子层）

## 缺口
页面是三代树（爷爷 pillar → 爸爸 sub-pillar → 孙子 cluster）。AssignMenu 原渲染只到两级：遍历 pillars，每个 pillar 下 `filter(pillarId===pillar.id)` 只画直属子页。于是爸爸(pillarId=爷爷)显示、但孙子(pillarId=爸爸)不显示 → 词没法指派到孙子。`onAssign(pageId)` 对任意 id 都能绑（处理器/reducer/数据层早已支持），唯一缺的是把孙子渲染出来。

## 改动（仅 AssignMenu.tsx）
1. **pillars 取数源**（L59-60）：从 `filtered` 改为 `pages` 全集取 pillar——保证树结构不被搜索打散。
2. **page list 渲染重写**（L119-204）：
   - **搜索态**（search 非空）：渲染 `filtered` 的扁平列表，每行带正确 RoleMark + 可点 onAssign——任意层级(含孙子)被搜到都能直接指派。
   - **非搜索态**：三级树。pillar(pl-4) → directChildren=`pages.filter(pillarId===pillar.id)`(pl-8，按 child.role 上对应 RoleMark) → 若 child 是 sub-pillar，再 grandchildren=`pages.filter(pillarId===child.id)`(pl-12，cluster RoleMark)。三层封顶，每层可点 onAssign。无重复渲染（孙子 pillarId=爸爸≠爷爷，不进 directChildren）。
3. **new-cluster 父级下拉**（L283-286）：从仅 pillar 扩为 `pillar || sub-pillar`，sub-pillar 选项加 `└` 前缀区分——支持"新建集群"时把孙子直接挂到某个爸爸底下。onCreateAndAssign 签名/reducer 未动（父是爸爸时 pillarId=爸爸id 已能处理）。

不动 reducer/数据/主表/格子/抽屉/Inspector。
