## 1. 已修（代码）

### P1 · 全站安全响应头 + 关闭 X-Powered-By
**文件**：`next.config.ts`（整文件重写）

- `poweredByHeader: false` —— 去掉 `X-Powered-By: Next.js` 指纹。
- `headers()` 对 `/:path*` 注入：
  | 头 | 值 | 作用 |
  |---|---|---|
  | `X-Frame-Options` | `DENY` | **强制生效**，当场堵死点击劫持（体检确认可被 iframe 嵌套） |
  | `X-Content-Type-Options` | `nosniff` | 禁 MIME 嗅探 |
  | `Referrer-Policy` | `strict-origin-when-cross-origin` | 跨站只带 origin |
  | `Strict-Transport-Security` | `max-age=63072000; includeSubDomains; preload` | 强制 HTTPS 两年 |
  | `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | 关高危权限 |
  | `Content-Security-Policy-Report-Only` | 见下 | XSS 兜底白名单，**先观察不拦截** |

- CSP（Report-Only）：`default-src 'self'`；`script-src 'self' 'unsafe-inline' https://static.cloudflareinsights.com`；`style-src 'self' 'unsafe-inline'`；`img-src 'self' data: blob:`；`font-src 'self'`；`connect-src 'self' https://cloudflareinsights.com`；`frame-ancestors 'none'`；`base-uri 'self'`；`form-action 'self'`；`object-src 'none'`。
  - 用 Report-Only 是因为：现在只上报「本会被拦」、不真拦，**零翻车风险**；点击劫持已由 XFO 强制堵死，不依赖 CSP。
  - `'unsafe-inline'` 保留原因：Next App Router 注水需内联 bootstrap 脚本、登录页有 style 属性内联样式，当前无 nonce 方案。**转正前若想去掉 unsafe-inline，需引入 nonce（改 proxy.ts 注入 + 各内联点带 nonce）**。

### P2 · n8n 回调防重放窗口
**文件**：`src/app/api/n8n/callback/route.ts`（schema 解析后、DB 写入前插入 7 行）

- 新增：拒收 `ts` 偏离当前时间超过 `N8N_CALLBACK_MAX_SKEW_SEC`（默认 **3600 秒**）的事件，返回 `422 {"error":"stale_timestamp"}`；设 `0` 关闭。

## 3. 运维建议（P2/P3/P4，需在服务器/Cloudflare/n8n 侧执行，代码侧已就绪）

**P2 收尾（最高价值，强烈建议）**
1. **轮换 `N8N_CALLBACK_TOKEN`**：生产环境变量改为强随机值（`openssl rand -hex 32`），并同步改 n8n W01 workflow 里回调请求头的 `x-n8n-token`。弱默认 `weslamic0125124737` 必须废弃。
2. **收敛 `N8N_CALLBACK_IP_ALLOWLIST`**：查到 n8n(Railway) 出口固定 IP 后，把生产该变量从 `*` 改为该 IP（或在 Cloudflare WAF 对 `/api/n8n/callback` 加来源 IP 规则）。
3. （可选，需改 n8n 侧）升级为 HMAC 请求签名——比共享 token 更强，但要 n8n 与 APP 双侧协同改造，本次未做。

**P3（无需改本仓库代码）**
- 本仓库不含 PostHog/RudderStack。请在 **Cloudflare 控制台**确认 `/app/*` 是否被边缘注入了 session recording/录屏类脚本；若有，评估对后台关键词/主题策略/admin 操作**关录屏或脱敏**。

**P4（验证类，建议靠 Cloudflare 边缘层）**
- 登录限流/失败锁定：当前无（`authorize` 在 Credentials 里，serverless 多实例下进程内计数不可靠）。单管理员场景**推荐用 Cloudflare Rate Limiting 规则**护 `/api/auth/callback/credentials`，比应用内自造更稳。
- 用户名枚举：**已无问题**——`authorize` 对「用户名错」「密码错」都返回 `null`，前端统一报 `CredentialsSignin`，不可区分 ✓。
- session cookie 的 `Secure`+`SameSite`：NextAuth v5 默认在 HTTPS 下 `__Secure-`/`Lax`，生产 HTTPS 自动满足；二次门 cookie 用 `__Host-` 前缀 + httpOnly + secure(prod) ✓。
- sitemap.xml 404：属内部工具（全站打回 /login），无对外 sitemap 需求，**按需再补**，不影响安全。

**CSP 转正流程（下一程）**
1. 当前 Report-Only 跑数日，打开浏览器 DevTools Console 看有无 `Content-Security-Policy-Report-Only` 违规上报。
2. 若只有自身资源、无新外域 → 把 `next.config.ts` 里响应头名从 `Content-Security-Policy-Report-Only` 改为 `Content-Security-Policy` 即转正。
3. 若发现新外域（新接的统计/CDN/字体）→ 先补进对应 `*-src` 白名单再转正。
4. 进阶：若要去掉 `script-src 'unsafe-inline'`，需在 `src/proxy.ts` 生成 per-request nonce 并下发，各内联脚本带 `nonce`。
