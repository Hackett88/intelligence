# Stage 1 · 小范围导入测试 + 准确性验证报告

## 结论先行

**采集方案确定：复刻 GSC 思路成立 —— 用已登录浏览器（puppeteer 连本地 Chrome）在页面上下文里 POST GA4 内部数据接口 `venus`，拿结构化 JSON，零独立凭证。** 实测数据与 GA4 UI 一致，全部 4 个保留字段可取/可派生。

> ⚠️ 与背景 researcher 的结论分歧已用实测拍死：researcher 判定"逆向 UI 内部接口不可行（混淆 RPC / SAPISIDHASH / 无先例），必须官方 Data API + OAuth + GCP project"。但**实测证明 GA4 的数据端点 `/analytics/app/data/v2/venus` 是干净 JSON、仅需 cookie + `x-gafe4-xsrf-token`、返回值与 UI 精确一致、无需任何 GCP/OAuth/凭证**。researcher 是对通用 wiz/batchexecute RPC 的推断，没命中真正的 venus 端点。以实测为准。researcher 的其余告诫（采样/阈值标志位、per-session 口径要自己算）有效，已采纳。

## 一、采集机制（已验证）

- **端点**：`POST https://analytics.google.com/analytics/app/data/v2/venus?accessmode=read&dataset=a389587172p530847425&hl=zh_CN`
- **认证**：同源请求自动带 cookie（登录态）+ 请求头 `x-gafe4-xsrf-token`（值 = cookie `GA_XSRF_TOKEN`，页面可读）。**无 SAPISIDHASH、无 OAuth、无 service account。** 与 GSC 一样骑用户已登录会话。
- **puppeteer 落地形态**：`page.evaluate(async () => fetch('/analytics/app/data/v2/venus?...', { method:'POST', headers:{'x-gafe4-xsrf-token': <读cookie>, 'content-type':'application/json'}, body: JSON.stringify(payload), credentials:'include' }))` —— 同源 + 凭证自动，和现有 `fetcher.ts` 同一个 CDP 连接即可。
- **请求体结构**（实测模板）：
  ```
  { entity:{propertyId:"530847425", identityBlendingStrategy:2},
    requests:[{ dimensions:[{name:"page_path"}], dimensionFilters:[], metricFilters:[],
      metrics:[{name:"active_users"},...], dateRanges:[{startDate,endDate}],
      rowAxis:{fieldNames:["page_path"], sorts:[{fieldName:"active_users",sortType:1,isDesc:true}], limit, offset} }],
    guid:"..." }
  ```
- **响应**：`)]}',` 前缀后是 JSON；`default.responses[0].responseRows[]`，每行 `dimensionCompoundValues[].value` + `metricCompoundValues[].value`；`numberOfSamplesRead[]` 非空 = 被采样；`metadata.dataProcessingStatusInfo` 含数据新鲜度。
- 证据：`test-evidence/ga4-venus-response-1151.network-response`（原始抓包）。

## 二、字段名落定（snake_case）

| 我们的字段 | venus 取法 | 状态 |
|---|---|---|
| 活跃用户 activeUsers | metric `active_users` | ✅ 直接 |
| 互动率 engagementRate | `engaged_sessions` ÷ `sessions`（`engagement_rate` 本身 500 无效）→ **派生** | ✅ 派生 |
| 平均互动时长(每会话) | `user_engagement_duration` ÷ `sessions`（per-session，对齐 UI；`average_session_duration` 是另一口径，坑）→ **派生** | ✅ 派生 |
| 来源国 topCountries | 维度 `country`（+ 限定到某 page_path）| ⚠️ 维度可用；**per-URL 过滤语法待定**（见下） |
| 维度 page 对齐 | `page_path` ✅ / `landing_page` ✅（`page_path_and_screen_class`、`landing_page_plus_query_string` 均 500 无效） | ✅ |

其它已验证可用（备用）：`screen_page_views`、`new_users`、`conversions`(关键事件)。无效：`engagement_rate`/`average_session_duration`/`bounce_rate`/`key_events`/`total_revenue`（后两者本就裁掉了）。

## 三、准确性验证（与 GA4 UI 对照）

- `landing_page` `/ar/blogs/...boy-name` = **987** 活跃用户 → 与 GA4 探索界面该行显示的 987 **完全一致**。
- `country` US = **1089** → 与探索界面 United States 列总计 1,089 **完全一致**。
- 5 个代表页全量派生结果（28 天窗）：

| URL | 活跃用户 | 互动率 | 平均互动时长/会话 |
|---|---|---|---|
| /collections/zikr-ring/products/zikr-ring | 1043 | 47.8% | 20s |
| /ar/blogs/…muslim-boy-name | 989 | 50.9% | 34s |
| / | 787 | 62.1% | 19s |
| /collections/zikr-ring | 527 | 61.2% | 35s |
| /pages/faithcreator | 435 | 64.6% | 17s |

互动时长 17–35s 与「网页和屏幕」报告先前实测的 12–43s 量级吻合。互动率落在 47–65%，与 Stage-阈值校准（60/45）口径一致。

## 四、必须带进 Stage 2 的发现 / 风险

1. **采样**：28 天窗下 session 类指标 `numberOfSamplesRead` 非空（被采样）。`active_users`/`country`/`user_engagement_duration` 某些查询未采样。**生产管道必须读采样标志，被采样的数据打"近似"标记**；可考虑缩短窗口或换非采样的标准报告端点降低采样。
2. **per-URL 来源国过滤语法未定**：我猜的 `dimensionFilters:[{fieldName,stringFilter:{matchType,value}}]` 返回 500。两条出路：① 抓一个 UI 上带页面过滤的请求逆出正确 filter 结构；② 改用 `[page_path, country]` 双维度一次拉全、客户端按 page 分组（省去 filter）。Stage 2 定。
3. **landing_page vs page_path 口径**：两者都可用、值略不同（落地会话 vs 全量浏览）。需在 Stage 2 明确：与 GSC 点击对齐用 `landing_page`（落地口径），还是用 `page_path`（页面浏览口径）。倾向 landing_page（与 GSC 点击同为"落地"语义）。
4. **渠道收窄**：当前未按 organic 收窄。是否要 `session_default_channel_group = Organic Search` 过滤以与 GSC 同源，Stage 2 定（取决于展示语义）。
