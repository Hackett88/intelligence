# URL 抽屉「内容优化追踪」功能

## 意图

曝光高、点击低的页需要做内容优化。痛点：优化后常忘记哪些页优化过、哪些没优化，也无法追踪优化后的效果。
需求：在 URL 抽屉里能「标记优化」，标记后流量趋势能出现一行「优化后累计」跟总数据对比，带版本控制——
每优化一轮版本 +1，总数据不受影响。

## 三点拍板口径（用户确认）

1. **版本行口径**：从该次优化日至今的累计（切版本 = 换起算日，与总计行同列对齐比对）。
2. **记备注**：点「标记优化」时弹内联输入框记一句「改了什么」（可留空）。
3. **误点撤销**：提供「撤销上一次优化」（弹出最新版本，不改历史版本）。

| UI-2 趋势 | `PageTrendChart.tsx` `PageTrendSection` | SUMMA 由 flex-wrap 改为**上下对齐网格**：列 [标签][起算日][曝光][点击][CTR]；总计行 + 优化后行（◄ v{n} ► 切版本）；无数据诚实空态；默认停最新版本 |

**关键设计**：优化后累计**前端算**——`series.filter(d => d.date >= 优化日期).sum()`。趋势接口已返回每日序列（YYYY-MM-DD），
优化日期同口径，字符串比较即可，无需新数据管道。批量增量趋势弹窗不传 optimizations → 行为与现状完全一致（不碰坏）。

## 备注 / 后续

- 优化日期取洛杉矶日历日，与趋势 series（gsc_page_daily.date，太平洋日）同口径，字符串比较可靠。

- 单管理员低并发，append/undo 走「读→算→upsert」不加事务（与 overrides 同风格）。
